==================================================
CORE PRINCIPLE
==================================================

The slide should be a VISUAL MAP of the explanation.

The presenter provides the detailed explanation verbally.

The audience should be able to scan a slide in approximately 5–8 seconds and understand its main message.

When choosing between:

MORE TEXT
vs.
MORE WHITESPACE

PREFER MORE WHITESPACE.

When choosing between:

LONG EXPLANATION
vs.
SHORT TECHNICAL PHRASE

PREFER THE SHORT TECHNICAL PHRASE.

==================================================
TEXT STYLE
==================================================

Use:

- short labels;
- short phrases;
- keywords;
- technical identifiers;
- arrows;
- diagrams;
- concise relationships.

Avoid:

- paragraphs;
- long explanatory bullets;
- full sentences when they are not necessary;
- repeated explanations;
- marketing-style descriptions;
- documentation-style wording.

A good content block should ideally contain:

LABEL
+
ONE SHORT SUPPORTING PHRASE

For example:

Instead of:

"Triage Automation: Eliminates developer toil in analyzing repetitive suite failures and selector breakages."

Use:

**Triage automation**
Automated failure analysis

Instead of:

"Operational Context: Engineered for unattended nightly CI/CD regression runs and local pre-commit verification."

Use:

**CI / Local**
Nightly + pre-commit execution

Instead of:

"Beyond Static Reports: Transcends Allure's HTML logs by parsing raw failure traces into stateful resumable batches."

Use:

**Actionable failures**
Raw traces → resumable batches

Instead of:

"Context Efficiency: Eliminates duplicate file reads and redundant AI passes by grouping co-located failures."

Use:

**Context efficiency**
Grouped failures → focused context

==================================================
STRICT DENSITY RULES
==================================================

Apply these constraints wherever possible:

- Maximum 4 content blocks per column.
- Maximum 2 lines of supporting text per content block.
- Prefer 3–8 words for supporting phrases.
- Avoid bullets longer than approximately 8–12 words.
- Do not use paragraphs inside cards.
- Do not repeat information already represented visually.
- Do not explain a diagram in a paragraph if the diagram can communicate it.
- Use technical keywords instead of prose when possible.

If a technical concept requires more explanation, keep the short version on the slide and move the detailed explanation into the SPEAKER NOTES.
